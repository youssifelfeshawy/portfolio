Network Documentation

Overview

A network is a collection of devices connected together so they can communicate and share resources. It can be as small as two computers connected at home, or as large as millions of servers spread across the globe forming the Internet.

OSI Model

When two devices from different manufacturers need to communicate — a Cisco router with a Juniper router, a Windows PC with a Linux server — they can do so because everyone follows the same universal rules defined by the OSI (Open Systems Interconnection) model.

The OSI model divides the complex job of networking into 7 separate layers. Each layer has a specific responsibility and only communicates with the layers directly above and below it. This clean separation means manufacturers can build equipment for one layer without affecting how other layers work.

7

Layer 7 — Application: provides the interfaces and protocols needed by the user's software, enabling applications on different end-systems to communicate. Examples: HTTP (Hypertext Transfer Protocol), DNS (Domain Name System), FTP (File Transfer Protocol), SMTP (Simple Mail Transfer Protocol).

6

Layer 6 — Presentation: translates data between the application's format and a standard network format. Also handles encryption, decryption, compression, and decompression. Examples: SSL/TLS (Secure Sockets Layer / Transport Layer Security), JPEG, ASCII.

5

Layer 5 — Session: establishes, maintains, and terminates communication sessions between two applications. Examples: NetBIOS, RPC (Remote Procedure Call).

4

Layer 4 — Transport: provides end-to-end delivery of data between applications. Handles segmentation, error recovery, and flow control. Adds a header containing source and destination port numbers. Examples: TCP (Transmission Control Protocol), UDP (User Datagram Protocol).

3

Layer 3 — Network: handles logical addressing and routing of packets across different networks through intermediate routers. Adds a header containing source and destination IP (Internet Protocol) addresses. Examples: IPv4 (Internet Protocol version 4), IPv6, OSPF (Open Shortest Path First).

2

Layer 2 — Data Link: handles communication between two directly connected devices on the same local network. Creates frames by adding a header (source and destination MAC (Media Access Control) addresses) and a trailer (FCS (Frame Check Sequence) for error detection). Examples: Ethernet, Wi-Fi (802.11).

1

Layer 1 — Physical: converts frames into raw bits and transmits them over the physical medium — electrical signals in copper cable, light pulses in fiber optic cable, or electromagnetic waves in wireless.

Encapsulation

When data is sent, it travels down the OSI (Open Systems Interconnection) layers on the sending device, across the physical medium, then back up the layers on the receiving device. As data moves down, each layer adds its own header — and sometimes a trailer. This process is called encapsulation. The data unit at each layer has its own name called a PDU (Protocol Data Unit).

  • Segment (TCP) / Datagram (UDP): the L4PDU (Layer 4 Protocol Data Unit). Application data plus a TCP (Transmission Control Protocol) or UDP (User Datagram Protocol) header containing port numbers and transport information.
  • Packet: the L3PDU (Layer 3 Protocol Data Unit). The segment or datagram plus an IP (Internet Protocol) header containing source and destination IP addresses.
  • Frame: the L2PDU (Layer 2 Protocol Data Unit). The packet plus an Ethernet header (Media Access Control addresses) and a FCS (Frame Check Sequence) trailer for error detection.
  • Bits: the L1PDU (Layer 1 Protocol Data Unit). The frame converted into raw electrical, light, or radio signals for physical transmission.
Note:

A payload at any layer means everything that layer is carrying, excluding its own header and trailer. For example, the payload of an Ethernet frame (L2PDU) is the IP packet (L3PDU) inside it.

At the receiving device, the process reverses — each layer strips its own header and passes the data upward. This is called de-encapsulation.

Layer 1: The Physical Layer

The Physical Layer is the foundation of all networking. It defines the physical medium that carries raw bits — electrical signals on copper wire, light pulses through fiber optic cable, or radio waves through the air. Every higher layer depends on this layer to physically move data from one place to another.

Transmission Media:-

The physical medium is what carries the actual signal between devices. All transmission media fall into one of two categories:

  • Wired (guided) media: signals travel through a physical cable that guides the signal from source to destination. Examples: UTP (Unshielded Twisted Pair) copper cable, fiber optic cable, coaxial cable.
  • Wireless (unguided) media: signals travel through the air as electromagnetic waves without any physical conductor. Examples: Wi-Fi local networks, cellular networks (4G/5G), satellite links, terrestrial microwave.

The two main wired media used in modern networks are UTP (Unshielded Twisted Pair) copper cable and fiber optic cable. Each is covered in detail below.

UTP (Unshielded Twisted Pair) Copper Cables:-

UTP (Unshielded Twisted Pair) is the standard copper cable used in wired Ethernet networks. It contains 4 pairs of copper wires — 8 wires total — twisted together inside a plastic outer jacket. Twisting each pair reduces EMI (Electromagnetic Interference) that would otherwise corrupt the signal.

The RJ-45 Connector:-

UTP (Unshielded Twisted Pair) cables terminate with an RJ-45 connector — the standard plastic plug used for all wired Ethernet connections. It has 8 pins, each corresponding to one of the 8 wires. How those pins are wired at each end determines the cable type.

10BASE-T and 100BASE-T — Pin Usage:-

At speeds of 10 Mbps (10BASE-T) and 100 Mbps (100BASE-TX, also called Fast Ethernet), only 4 of the 8 wires carry data — one pair to transmit and one pair to receive:

Pins 1 & 2: Transmit (TX) from the PC or Router → Receive (RX) on the Switch.
  • Pins 3 & 6: Receive (RX) on the PC or Router ← Transmit (TX) from the Switch.

Straight-Through vs. Crossover Cables:-

Straight-Through: pins are wired identically at both ends (1→1, 2→2, 3→3, 6→6). Used when connecting different device types — PC to Switch, Router to Switch — because TX pins on one device type align with RX pins on the other.
Crossover: pairs are swapped at one end (1→3, 2→6, 3→1, 6→2). Used when connecting the same device types — PC to PC, Switch to Switch, Router to Router — so that TX connects to RX rather than TX to TX.

Gigabit and 10-Gigabit Ethernet:-

At speeds of 1 Gbps (1000BASE-T) and 10 Gbps (10GBASE-T), all 8 wires are used across all 4 pairs. Each pair operates bidirectionally — the same pair simultaneously carries signals in both directions using advanced signal processing. This bidirectionality enables the dramatically higher throughput.

Fiber Optic Cables:-

Fiber optic cables transmit data as pulses of light through a glass core, rather than electrical signals through copper. This enables much longer distances, higher speeds, and complete immunity to electromagnetic interference — making fiber the preferred medium for inter-building links, WAN (Wide Area Network) connections, and high-security environments.

Fiber Cable Structure (inside to outside):-

  • Fiberglass core: the medium through which light pulses travel.
  • Cladding: a glass layer surrounding the core with a different refractive index. This difference causes total internal reflection — light cannot escape through the cladding and stays confined to the core.
  • Buffer coating: a protective plastic layer that cushions the fragile glass.
  • Outer jacket: the tough outer sheath that protects the entire assembly from physical damage and the environment.

SFP (Small Form-factor Pluggable) Transceivers:-

Standard network device ports use electrical signals, so a fiber optic cable cannot be plugged directly into a regular Ethernet port. To connect a fiber cable to a switch or router, a SFP (Small Form-factor Pluggable) transceiver is required — a compact, hot-swappable module that slots into an SFP port on the device. The SFP converts the device's electrical signals into optical signals for transmission, and converts incoming light signals back into electrical signals.

Each fiber connection uses two separate strands — one for transmitting (TX) and one for receiving (RX) — making fiber connections inherently full-duplex.

Single-Mode vs. Multi-Mode Fiber:-

  • MMF (Multi-Mode Fiber): uses a LED (Light Emitting Diode) light source and a wider core (50 or 62.5 micrometers). Light bounces along multiple paths (modes), which causes slight signal spreading (modal dispersion) that limits distance to roughly 550 meters. Cheaper than single-mode. Best suited for short distances inside buildings or data centers.
  • SMF (Single-Mode Fiber): uses a laser light source and an extremely narrow core (9 micrometers). Light travels in a single straight path with virtually no dispersion, enabling distances of 100 kilometers or more. More expensive. Used for long-distance runs between buildings, campuses, and WANs (Wide Area Networks).

Network Devices

Layer 1 devices operate purely on raw signals — they have no understanding of addresses or any higher-layer information. They simply receive a signal and retransmit it.

  • Hub: a basic Layer 1 device that connects multiple devices. When any device sends a signal, the hub amplifies and repeats it out of every other port with no intelligence about the intended destination. All devices share the same physical medium. Hubs are legacy technology replaced by switches.
  • Repeater: receives a signal, amplifies it to restore signal strength lost over distance, and retransmits it. Used to extend the maximum cable length of a network segment.

    • Frame Errors

    • Runt: a frame smaller than the minimum valid Ethernet frame size of 64 bytes. Typically caused by a collision or a malfunctioning network interface card (NIC).
    • Giant: a frame larger than the maximum valid Ethernet frame size of 1518 bytes (or 1522 bytes when an 802.1Q VLAN tag is present). Usually caused by a misconfigured device.

    Layer 2: The Data Link Layer

    Layer 1 defines how raw bits travel across a physical medium. Layer 2 organizes those bits into structured frames and ensures they reach the correct device on the local network. It introduces hardware addressing, error detection, and the intelligent devices — switches — that make selective forwarding possible.

    Layer 2 Responsibilities

    • Framing: packages raw bits into structured units called frames, each with a defined start, hardware addressing, data payload, and error-check trailer.
    • MAC (Media Access Control) Addressing: every device has a unique hardware address. Layer 2 uses these addresses to identify the source and destination of each frame on the local network.
    • Error Detection: a checksum in the frame trailer lets the receiving device verify the frame arrived uncorrupted.
    • Media Access Control: on shared media, Layer 2 defines the rules for which device may transmit at any given moment to prevent signal collisions.
    Note:

    Layer 2 only handles delivery between directly connected devices on the same local network. Delivering data across different networks is the job of Layer 3.

    Switches

    At Layer 1, a hub repeats every signal out of every port to every connected device — with no intelligence. If two devices transmit simultaneously, their signals collide on the shared medium and both transmissions are corrupted.

    A switch is the intelligent Layer 2 replacement for the hub. A switch reads the destination MAC (Media Access Control) address of each incoming frame and forwards it only out the correct port — toward the intended recipient, not every device.

    Duplex Modes:-

    • Half-Duplex: a device can either send or receive at any moment — never both simultaneously. Requires Carrier Sense Multiple Access with Collision Detection (CSMA/CD). Used with hubs and legacy equipment.
    • Full-Duplex: a device can send and receive simultaneously on separate wire pairs. No collisions are possible. All modern switch-connected devices operate in full-duplex.

      • Collision Domains

      A collision domain is a network segment where two devices transmitting simultaneously cause a collision. The type of device determines the collision domain boundaries:

      • Hub: all ports share one collision domain. Any two devices can collide with each other.
      • Switch: each port is its own isolated collision domain. Devices on different switch ports can transmit simultaneously without any collision.

        • CSMA/CD

        When devices share a collision domain (as on a hub), they use CSMA/CD (Carrier Sense Multiple Access with Collision Detection) to manage access to the shared medium:

        • Carrier Sense: before transmitting, a device listens to the medium to check that it is currently idle.
        • Multiple Access: multiple devices share the same physical medium.
        • Collision Detection: if two devices transmit simultaneously and a collision occurs, both immediately stop and broadcast a jamming signal to alert all devices. Each then waits a random back-off period before retrying.
        Note:

        Carrier Sense Multiple Access with Collision Detection (CSMA/CD) only applies in half-duplex environments with shared collision domains. Modern switch-connected devices run full-duplex — CSMA/CD is disabled entirely.

      MAC (Media Access Control) Addresses:-

      Every network interface card (NIC) — in a laptop, phone, server, switch, or any networked device — has a MAC (Media Access Control) address permanently embedded by the manufacturer. The MAC address is how Layer 2 identifies devices on a local network.

      • 48 bits long (6 bytes) — written as 12 hexadecimal characters, for example AA:BB:CC:11:22:33.
      • Burned-In Address (BIA): permanently written into the hardware at the factory. Cannot be changed by software, though it can be spoofed at the operating system level.
      • Globally unique: no two network interface cards in the world should share the same MAC address.

      MAC Address Table — Switch Learning and Forwarding:-

      A switch maintains a MAC address table (also called a CAM (Content Addressable Memory) table) that maps each known MAC address to the switch port it was learned from. This table is built dynamically as frames arrive.

      FIGURE SPACE

      [ Figure: Switch learning: PC-A sends a frame with source MAC AA:BB:CC → switch records 'AA:BB:CC = Port 1' in its MAC table → switch looks up destination MAC → forwards only out the correct port ]

      • Learn: when a frame arrives, the switch reads the source MAC address and records it with the incoming port number in the MAC address table.
      • Forward: the switch looks up the destination MAC address. If found, the frame is sent only out that port (unicast forwarding). If not found, the frame is flooded out all ports except the one it arrived on — called unknown unicast flooding.
      • Aging: if a MAC address entry is not refreshed for 5 minutes, it is removed from the table. The switch will flood again until the address is relearned.

      clear mac address-table dynamic interface <INT>    → remove all entries learned on one interface

      VLANs and Trunking

      All devices on a switch by default share the same local network and broadcast domain. VLANs (Virtual Local Area Networks) divide a single physical switch into multiple isolated logical networks. To carry traffic from multiple VLANs across one cable, switches use trunking.

      LAN (Local Area Network) and Broadcast Domain:-

      • LAN (Local Area Network): a group of devices in a single location that are all part of the same network and can communicate directly at Layer 2.
      • Broadcast Domain: the set of all devices that receive a broadcast frame (destination MAC FF:FF:FF:FF:FF:FF) sent by any one member. By default, all ports on a switch are in the same broadcast domain.
      Note:

      Routers break broadcast domains — a broadcast does not cross a router. Switches alone do not break broadcast domains, but VLANs (Virtual Local Area Networks) let you create multiple separate broadcast domains within a single switch.

      VLANs (Virtual Local Area Networks):-

      A VLAN (Virtual Local Area Network) logically separates end hosts at Layer 2 — creating isolated broadcast domains within a single physical switch. VLANs are configured per interface on the switch. A switch will not forward traffic directly between hosts in different VLANs; to communicate across VLANs, traffic must be routed at Layer 3, which is covered in the inter-VLAN routing section of the Layer 3 chapter.

      Configuring Access Ports:-

      An access port belongs to exactly one VLAN and connects to end hosts such as PCs, printers, and servers. The end host is unaware of VLANs — the switch handles VLAN membership transparently.

      int range g0/1 - 4               → select multiple interfaces at once

      switchport access vlan 10        → assign the port to VLAN 10 (auto-created if it does not exist)

      show vlan brief                  → view all VLANs and which access ports belong to each

      Trunk Ports:-

      A trunk port carries traffic from multiple VLANs (Virtual Local Area Networks) over a single physical cable. Trunk ports are used on switch-to-switch and switch-to-router links where traffic from many VLANs must travel on the same connection.

      • Access ports: untagged — carry traffic for a single VLAN. Connect to end hosts.
      • Trunk ports: tagged — carry traffic for multiple VLANs simultaneously. Connect to other switches or routers.

      IEEE 802.1Q Trunking Protocol:-

      Two trunking protocols exist: the old Cisco-proprietary ISL (Inter-Switch Link), and the modern industry-standard IEEE 802.1Q (dot1q). IEEE 802.1Q is universal and used in all modern networks.

      When a switch sends a frame out a trunk port, it inserts a 4-byte IEEE 802.1Q tag into the Ethernet frame between the Source MAC Address and the Type/Length field. The receiving switch reads the tag to determine the VLAN, then strips it before delivering the frame to the destination host.

      Native VLAN:-

      The native VLAN is an IEEE 802.1Q feature. Frames belonging to the native VLAN are sent across a trunk port without an 802.1Q tag — they travel as plain untagged frames. When a switch receives an untagged frame on a trunk port, it assumes the frame belongs to the native VLAN.

      • Default native VLAN: VLAN 1 on all trunk ports.
      • Must match: the native VLAN must be configured identically on both ends of a trunk link. A mismatch sends frames to the wrong VLAN.
      • Security best practice: change the native VLAN to an unused VLAN (such as VLAN 1001) to prevent VLAN hopping attacks.

      Trunk Encapsulation Negotiation:-

      On switches that support both IEEE 802.1Q and ISL (Inter-Switch Link) encapsulation, DTP (Dynamic Trunking Protocol) can also negotiate which trunking encapsulation to use. The default trunk encapsulation mode on such switches is 'negotiate':

      switchport trunk encapsulation negotiate   → default on switches that support both ISL and dot1q — DTP negotiates which to use
      switchport trunk encapsulation dot1q       → explicitly set encapsulation to IEEE 802.1Q (recommended)

      When encapsulation is set to negotiate, ISL (Inter-Switch Link) is preferred over IEEE 802.1Q — if both switches support ISL, it will be selected. Regarding DTP frame placement: DTP frames are sent in VLAN 1 when using ISL (Inter-Switch Link), or in the native VLAN when using IEEE 802.1Q (the default native VLAN is VLAN 1, so in practice both default to VLAN 1).

      Best Practice:

      always set the trunk encapsulation explicitly with 'switchport trunk encapsulation dot1q' rather than relying on automatic negotiation. This ensures predictable behavior regardless of what the connected switch supports.

      STP (Spanning Tree Protocol)

      Network redundancy is critical — if one switch or link fails, traffic must continue through an alternate path. However, redundant Layer 2 links create loops, and loops are catastrophic in Ethernet networks. STP (Spanning Tree Protocol) automatically blocks redundant paths to prevent loops while keeping those paths on standby as instant backups.

      The Problem with Redundant Links:-

      Unlike IP (Internet Protocol) packets at Layer 3, Ethernet frames have no TTL (Time to Live) field — nothing naturally stops them from circulating forever in a loop.

      • Broadcast Storm: a broadcast frame (destination FF:FF:FF:FF:FF:FF) entering a loop is forwarded by every switch out every port indefinitely. Copies multiply rapidly. Within seconds, broadcast traffic consumes all available bandwidth and makes the network completely unusable.
      • MAC Address Flapping: in a loop, the same frame arrives on different switch ports repeatedly. The switch constantly updates its MAC address table, recording the same source MAC alternating between ports. This instability causes frames to be forwarded incorrectly and wastes switch resources.

      PVST+ (Per-VLAN Spanning Tree Plus) and STP Load Balancing:-

      Cisco switches run PVST+ (Per-VLAN Spanning Tree Plus) — a separate STP (Spanning Tree Protocol) instance runs independently for each VLAN. Different ports can be forwarding in VLAN 10 while blocking in VLAN 20. By assigning different root bridges per VLAN, traffic from different VLANs uses different physical paths — avoiding wasted redundant links and congestion on a single connection. This is called STP Load Balancing.

      STP (Spanning Tree Protocol) — IEEE 802.1D:-

      Classic STP (Spanning Tree Protocol), defined in IEEE 802.1D, is enabled by default on switches from all vendors. STP prevents Layer 2 loops by placing selected ports into a blocking state — disabling them from forwarding regular traffic. Blocked ports act as standby links that can activate if the primary path fails.

      Port StateForwards Traffic?Processes BPDUs?Description

      BlockingNoYes (receives only)Discards all regular traffic. Listens for BPDUs (Bridge Protocol Data Units) to detect topology changes. Activates if the active path fails.

      BPDUs (Bridge Protocol Data Units):-

      STP (Spanning Tree Protocol) switches communicate using BPDUs (Bridge Protocol Data Units). Hello BPDUs are sent out every interface every 2 seconds by default. If a switch receives a Hello BPDU on an interface, it knows that interface is connected to another switch — end hosts like PCs and routers do not send BPDUs.

      The Bridge ID:-

      Every switch in an STP topology has a Bridge ID (Bridge Identifier) — a unique value used to elect the root bridge and make all forwarding decisions. The Bridge ID has two components:

      • Bridge Priority: compared first when electing the root bridge. Default is 32,768 on all switches. In Cisco's PVST+ (Per-VLAN Spanning Tree Plus) implementation, this 16-bit field is split into a 4-bit Bridge Priority and a 12-bit Extended System ID (equal to the VLAN ID). So the default Bridge Priority in VLAN 1 is 32,768 + 1 = 32,769.
      • MAC Address: used as a tiebreaker when two switches have the same Bridge Priority. The switch with the numerically lower MAC address wins.

      [ Figure: Bridge ID structure: [4-bit Bridge Priority | 12-bit Extended System ID (VLAN ID) | 48-bit MAC Address] — total 64 bits ]

      Because the Extended System ID (VLAN ID) cannot be changed, the Bridge Priority can only be adjusted in increments of 4,096. Valid values: 0, 4096, 8192, 12288, 16384, 20480, 24576, 28672, 32768, 36864, 40960, 45056, 49152, 53248, 57344, 61440. To manually set the priority and make a specific switch the root bridge — for example because it is more reliable or better positioned in the network:

      spanning-tree vlan <vlan-id> priority <value>        → set a specific Bridge Priority (must be a multiple of 4096)
      spanning-tree vlan <vlan-id> root primary            → shortcut: sets priority to 24,576 (or 4,096 less than the current lowest, whichever wins)
      spanning-tree vlan <vlan-id> root secondary          → shortcut: sets priority to 28,672 — becomes root if the primary fails

      Root Bridge Election:-

      The first step of STP (Spanning Tree Protocol) is electing one switch as the root bridge — the reference point for the entire topology. All forwarding paths are calculated relative to the root bridge.

      When a switch powers on, it assumes it is the root bridge and sends Hello BPDUs advertising itself. If it receives a BPDU from a switch with a lower Bridge ID, it gives up its claim. Once all switches agree, only the root bridge generates original BPDUs — all other switches only forward them.

      • Election rule: the switch with the lowest Bridge ID becomes the root bridge. Bridge Priority is compared first; if equal, the lower MAC address wins.
      • Root bridge ports: all ports on the root bridge are automatically Designated Ports in the forwarding state. The root bridge never has a blocking port.

      STP Port Roles:-

      After the root bridge is elected, every port in the network is assigned one of three roles:

      Root Port:-

      Every non-root switch selects exactly one Root Port — the port with the best path to the root bridge. Root ports are placed in the forwarding state. The port on the opposite end of every root port is always a Designated Port.

      Tiebreaker order for root port selection:

      • Lowest Root Path Cost — the total cumulative cost of all links from this switch to the root bridge, based on link speed.
      • Lowest Neighbor Bridge ID — if costs are equal, prefer the port connected to the switch with the lower Bridge ID.
      • Lowest Neighbor Port ID — if the neighbor Bridge ID is also equal (e.g., two parallel links between the same switches), prefer the port connected to the neighbor's lower Port ID. Port ID = Port Priority (default 128) + Port Number. To influence which port a downstream switch selects as its root port, you can adjust the port priority on the upstream switch's interface: spanning-tree vlan <vlan-id> port-priority <value>
      Note:

      It is the neighbor switch's Port ID that is used to break ties — not the local switch's own Port ID.

      Designated Port:-

      Every network segment (every link between two switches) has exactly one Designated Port — the port that forwards traffic onto that segment. Designated ports are in the forwarding state. For links between two non-root switches, the designated port is chosen as follows:

      • The switch with the lower total root path cost makes its port the Designated Port.
      • If root path costs are equal: the switch with the lower Bridge ID makes its port the Designated Port.
      • The other switch's port becomes the Non-Designated (blocking) Port.

      Non-Designated Port (Blocking):-

      Any port that is neither a Root Port nor a Designated Port becomes a Non-Designated Port in the blocking state. This is the port STP disables to break the loop. It remains ready to transition to forwarding if the active path fails.

      STP Port States:-

      Each switch port in a STP (Spanning Tree Protocol) topology is always in one of four states. Two are stable and two are transitional — passed through when changing from blocking to forwarding.

      StateTypeSends/Receives Traffic?Sends/Receives BPDUs?Learns MAC Addresses?Duration

      ListeningTransitionalNoYes — sends and receives BPDUsNo15 seconds (Forward Delay timer)
      LearningTransitionalNoYes — sends and receives BPDUsYes15 seconds (Forward Delay timer)

      Blocking State:-

      Non-Designated ports remain stable in the Blocking state. A blocking port is effectively disabled to prevent loops — it does not send or receive regular network traffic, and it does not forward BPDUs. However, it does receive BPDUs so it can detect any change in the network topology. It does not learn MAC addresses — if regular traffic arrives on a blocking interface, it is dropped without updating the MAC address table.

      Listening State:-

      When a Blocking port must transition to Forwarding due to a topology change, it first enters the Listening state. Only ports with a Designated or Root role enter the Listening state — Non-Designated ports always remain Blocking. The Listening state lasts 15 seconds by default (Forward Delay timer). The port only sends and receives BPDUs — no regular traffic is forwarded and no MAC addresses are learned.

      Learning State:-

      After the Listening state, a Designated or Root port enters the Learning state — also 15 seconds long, using the same Forward Delay timer. The port still does not forward regular traffic, but it now learns MAC addresses. This allows the switch to build its MAC address table before the port starts forwarding, reducing unnecessary flooding.

      Forwarding State:-

      Root Ports and Designated Ports remain stable in the Forwarding state — normal operation. A Forwarding port sends and receives both BPDUs and regular traffic, and learns MAC addresses. Only switches forward BPDUs out of their Designated ports.

      Note:

      A Forwarding port can move directly to Blocking with no delay — blocking cannot create a loop. However, a Blocking port must always pass through Listening (15 s) and Learning (15 s) first — 30 seconds total — before reaching Forwarding. This prevents loops from accidentally forming. A blocking interface transitioning after Max Age expires takes 50 seconds total (20 s Max Age + 15 s Listening + 15 s Learning).

      STP Toolkit:-

      The STP Toolkit refers to a set of features that enhance, protect, and optimize STP (Spanning Tree Protocol) behavior: PortFast, BPDU Guard, BPDU Filter, Root Guard, and Loop Guard.

      PortFast:-

      PortFast allows a switch port to skip the Listening and Learning states and move immediately to the Forwarding state when it becomes active. This removes the 30-second delay that would otherwise occur when a device first connects.

      • Use only on ports connected to end hosts (PCs, servers, printers) — never on ports connected to other switches. Enabling PortFast on a switch-to-switch port could create a Layer 2 loop.
      int g#/#
      spanning-tree portfast                         → enable PortFast on this interface
      spanning-tree portfast trunk                   → enable PortFast on a trunk interface (use with caution)
      spanning-tree portfast disable                 → disable PortFast on this specific port

      To enable PortFast globally on all access ports (not trunk ports):

      spanning-tree portfast default                 → enables PortFast on all access ports automatically

      BPDU Guard:-

      BPDU Guard protects PortFast-enabled ports from accidentally receiving BPDUs (Bridge Protocol Data Units). If a BPDU Guard-enabled port receives a BPDU — indicating another switch has been connected — the port is immediately shut down (placed in an ErrDisable state) to prevent a potential loop.

      int g#/#
      spanning-tree bpduguard enable                 → enable BPDU Guard on this interface

      To enable BPDU Guard globally on all PortFast-enabled interfaces:

      spanning-tree portfast bpduguard default        → enables BPDU Guard on all PortFast ports

      ErrDisable and ErrDisable Recovery:-

      ErrDisable is a Cisco switch feature that automatically shuts down a port when a policy violation is detected — such as a BPDU Guard violation. The port enters an err-disabled state and stops forwarding traffic.

      To re-enable an err-disabled port, the underlying issue must be fixed first. Re-enabling without fixing the cause will immediately err-disable the port again. There are two ways to re-enable:

      • Manual: enter interface configuration mode and use 'shutdown' followed by 'no shutdown' to reset the port.
      • Automatic — ErrDisable Recovery: automatically re-enables err-disabled ports after a configurable timer expires. Disabled by default.
      errdisable recovery cause bpduguard                     → enable automatic recovery for BPDU Guard violations
      errdisable recovery interval <seconds>                  → set the recovery timer (default is 300 seconds / 5 minutes)
      show errdisable recovery                                → view ErrDisable Recovery status and timers

      BPDU Filter:-

      BPDU Filter prevents a port from sending BPDUs (Bridge Protocol Data Units). Unlike BPDU Guard, it does not disable the port if it receives a BPDU. Useful on ports connected to end hosts where sending BPDUs wastes bandwidth and exposes STP topology information unnecessarily. BPDU Filter can be configured in two ways:

      • Per-port (use with caution): the port will not send BPDUs and will ignore any BPDUs it receives. This effectively disables STP on the port entirely.
      spanning-tree bpdufilter enable
      • Default (recommended): enables BPDU Filter on all PortFast-enabled ports. If the port receives a BPDU, PortFast and BPDU Filter are automatically disabled and the port operates as a normal STP port.
      spanning-tree portfast [edge] bpdufilter default        → enable BPDU Filter on all PortFast-enabled ports

      Root Guard:-

      Root Guard protects the STP topology by preventing an unauthorized switch from becoming the root bridge. When enabled on an interface, if that interface receives a superior BPDU — one with a lower Bridge ID than the current root bridge — the port is placed into a Broken (Root Inconsistent) state, effectively disabling it.

      A good practice is to enable Root Guard on all ports connecting to switches outside of your administrative control.

      int g#/#
      spanning-tree guard root                               → enable Root Guard on this interface

      A Root Guard-disabled port will not forward data frames and will discard any frames it receives. Once the superior BPDUs stop being received and their Max Age (20 seconds by default) expires, the port is automatically re-enabled.

      Loop Guard:-

      Loop Guard protects against unidirectional link failures — where data flows in only one direction between two switches. This is more common with fiber optic cables than copper UTP, due to the separate TX and RX strands. Causes include damaged cables, faulty connectors, or faulty SFP transceivers.

      Without Loop Guard, if a Root or Non-Designated port stops receiving BPDUs due to a unidirectional failure, the Max Age timer eventually expires and the port transitions to Forwarding — potentially creating a loop. Loop Guard prevents this by placing the port into a Broken (Loop Inconsistent) state instead. The port remains up/up physically but STP blocks it. If BPDUs are received again, the port is automatically re-enabled.

      • Loop Guard should be enabled on: Root Ports and Non-Designated Ports — ports that are supposed to be receiving BPDUs.
      spanning-tree guard loop                               → enable Loop Guard on a specific interface
      spanning-tree loopguard default                        → enable Loop Guard on all ports globally
      spanning-tree guard none                               → disable Loop Guard on a specific port

      Root Guard vs. Loop Guard:-

      Root Guard and Loop Guard are mutually exclusive — they cannot both be enabled on the same port. Their purposes are opposite:

      • Root Guard: applied to Designated Ports — prevents them from becoming Root Ports by blocking superior BPDUs.
      • Loop Guard: applied to Root and Non-Designated Ports — prevents them from becoming Designated Ports when BPDUs stop arriving.

      If both are configured on the same port, the more specific configuration wins. If Loop Guard is enabled globally and Root Guard is then configured on a specific port, Root Guard takes effect on that port and Loop Guard is disabled there.

      RSTP (Rapid Spanning Tree Protocol) — IEEE 802.1w:-

      RSTP (Rapid Spanning Tree Protocol), standardized as IEEE 802.1w and implemented in Cisco switches as Rapid PVST+, is the modern replacement for Classic STP. Its key advantage is dramatically faster convergence — adapting to topology changes in seconds rather than up to 50 seconds with Classic STP.

      RSTP Port States:-

      Rapid STP simplifies the port states compared to Classic STP. The Listening state is removed entirely, and the Disabled and Blocking states are merged into a single Discarding state:

      Classic STP StateRSTP StateNotes
      DisabledDiscardingPort is administratively shut down.
      BlockingDiscardingPort is enabled but blocking traffic to prevent loops.
      ListeningRemovedThe Listening state does not exist in RSTP.
      LearningLearningSame as Classic STP — learns MAC addresses but does not forward traffic.
      ForwardingForwardingSame as Classic STP — fully operational.
      Note:

      Classic STP (IEEE 802.1D) uses destination MAC address 0180.C200.0000 for BPDUs. Cisco's PVST+ uses 0100.0CCC.CCCD. Rapid STP is backward compatible with Classic STP — interfaces connected to a Classic STP switch will automatically operate in Classic STP mode, reverting to the full Blocking → Listening → Learning → Forwarding process with the original timers.

      RSTP Port Roles:-

      Rapid STP retains the Root Port and Designated Port roles from Classic STP, but splits the Non-Designated port role into two distinct roles:

      • Alternate Port: a Discarding port that receives a superior BPDU from another switch. It is the best alternative path to the root bridge. If the Root Port fails, the Alternate Port can move immediately to Forwarding without waiting — this is equivalent to the classic optional UplinkFast feature, but is built into RSTP automatically.
      • Backup Port: a Discarding port that receives a superior BPDU from another interface on the same switch. This only occurs when two interfaces on the same switch are connected to the same collision domain (via a hub). Hubs are not used in modern networks, so this role is rarely seen. The interface with the lowest Port ID becomes the Designated Port; the other becomes the Backup Port.

      RSTP BPDU Behavior:-

      In Classic STP, only the root bridge originates BPDUs — all other switches simply forward the BPDUs they receive. In Rapid STP, every switch originates and sends its own BPDUs from its Designated ports every Hello interval (2 seconds by default).

      RSTP also ages out neighbor information much faster. Classic STP waits 10 Hello intervals (20 seconds — the Max Age timer) before considering a neighbor lost. Rapid STP considers a neighbor lost if it misses 3 consecutive BPDUs (6 seconds). When a neighbor is considered lost, the switch immediately flushes all MAC addresses learned on that interface.

      RSTP Link Types:-

      Rapid STP classifies each port into one of three link types, which determines how quickly it can transition to Forwarding. The link type is detected automatically, but can also be manually configured when needed:

      • Edge: a port connected directly to an end host (PC, server, printer). Moves immediately to Forwarding without negotiation — equivalent to Classic STP's PortFast. Configured with: spanning-tree portfast. Edge ports are built into RSTP automatically.
      • Point-to-Point: a direct full-duplex connection between two switches. RSTP can rapidly negotiate Forwarding using a handshake process. Detected automatically in full-duplex.
      • Shared: a connection to a hub operating in half-duplex. Must use Classic STP timers and transition process. Detected automatically in half-duplex.

      To manually override the detected link type when needed:

      spanning-tree link-type <point-to-point|shared>       → manually set the link type on this interface
      Note:

      Two Classic STP optional features — UplinkFast (fast failover for Root Ports) and BackboneFast (fast recovery from indirect failures) — are both built into RSTP automatically. You do not need to configure them separately when using Rapid PVST+.

      EtherChannel

      When multiple links connect two switches, Spanning Tree Protocol disables all but one to prevent loops — leaving redundant bandwidth unused. EtherChannel bundles multiple physical interfaces together into a single logical interface, allowing all links to carry traffic simultaneously while STP sees only one connection.

      Network Design Context:-

      In a typical campus network, there are two important switch roles:

      • Access Layer Switch: the switch that end hosts (PCs, phones, printers) connect directly to. This is the edge of the network.
      • Distribution Layer Switch: the switch that access layer switches connect to. It aggregates traffic from multiple access switches and connects them to the rest of the network or the internet.

      When the total bandwidth of all end-host-facing interfaces on an access switch exceeds the uplink bandwidth to the distribution switch, this is called oversubscription. Some oversubscription is acceptable, but too much causes congestion.

      Connecting two switches with multiple links without EtherChannel causes Spanning Tree Protocol to block all links except one — the redundant links carry no traffic unless the active link fails. EtherChannel solves this by making STP treat the entire bundle as a single interface, allowing all physical links to forward simultaneously.

      FIGURE SPACE

      [ Figure: Two switches connected by 4 physical links: without EtherChannel, STP blocks 3 of them. With EtherChannel, all 4 links are active and treated as one logical interface by STP. ]

      How EtherChannel Works:-

      EtherChannel (also called Port Channel or LAG (Link Aggregation Group)) groups multiple physical interfaces into one logical interface. Traffic is distributed across the physical links using a load-balancing algorithm based on flows — a flow being a communication between two specific nodes.

      All frames belonging to the same flow are always sent over the same physical interface. This guarantees in-order delivery within each flow. Sending frames from the same flow over different physical interfaces could cause out-of-order arrival, which causes problems for higher-layer protocols.

      Load-Balancing Methods:-

      The EtherChannel load-balancing algorithm selects which physical interface to use based on a hash of one or more packet fields. The available inputs are:

      • src-mac: source MAC address.
      • dst-mac: destination MAC address.
      • src-dst-mac: source and destination MAC addresses (default on many switches).
      • src-ip: source IP address.
      • dst-ip: destination IP address.
      • src-dst-ip: source and destination IP addresses.
      port-channel load-balance <method>          → change the load-balancing method (global config mode)
      show etherchannel load-balance              → view the current load-balancing method

      Layer 3: The Network Layer

      Layer 2 delivers frames between devices on the same local network. Layer 3 makes communication possible between devices on completely different networks — anywhere in the world. It introduces IP addresses, routers, and the logic needed to find the best path from any source to any destination.

      Network Devices at Layer 3 — Routers:-

      A router is the primary Layer 3 device. Its job is to receive packets, examine the destination IP (Internet Protocol) address, and forward each packet out the correct interface toward its destination — hop by hop across the network. Routers connect different networks to each other, enabling global communication that Layer 2 switches cannot provide.

      Layer 3 has three core responsibilities, all performed by routers:

      • Logical Addressing: IP (Internet Protocol) addresses uniquely identify every device across any network in the world — unlike MAC addresses, which are only meaningful within a single local network. IP addresses stay the same end-to-end from source to destination, while MAC addresses change at every single hop.
      • Routing: routers examine the destination IP address of each packet and forward it along the best available path across the network.
      • Encapsulation: at each hop, the router strips the incoming Layer 2 frame (L2PDU), reads the Layer 3 IP address, makes a routing decision, then re-encapsulates the packet (L3PDU) in a brand new Layer 2 frame for the next link. The IP header — added at Layer 3 and containing source and destination IP addresses — is what the router uses to make these decisions.

      [ Figure: Packet traveling through 2 routers: Source → Router 1 (strips L2 frame, reads IP, creates new L2 frame) → Router 2 (same process) → Destination. IP addresses unchanged throughout; MAC addresses change at every hop. ]

      IPv4 (Internet Protocol version 4) Addressing:-

      IPv4 (Internet Protocol version 4) is the most widely used Layer 3 protocol. An IPv4 address is a 32-bit number written in dotted-decimal notation — four groups of 8 bits (called octets) separated by dots.

      Example: the address 192.168.1.100 in binary is 11000000 . 10101000 . 00000001 . 01100100

      FIGURE SPACE

      [ Figure: IPv4 address 192.168.1.100 shown across four 8-bit octets in binary. Subnet mask 255.255.255.0 (/24) below it, with the network/host boundary between the 3rd and 4th octets. ]

      Network Portion and Host Portion:-

      A subnet mask divides an IPv4 address into two parts:

      Network portion: identifies which network the device belongs to. All devices on the same network share an identical network portion.
      • Host portion: identifies the specific device within that network. Must be unique within the network.

      Example: 192.168.1.100 with mask /24 (255.255.255.0) — network portion: 192.168.1, host portion: .100.

      Special IPv4 Addresses:-

      Network Address (host portion all zeros — e.g., 192.168.1.0/24): represents the network itself. Used in routing tables to refer to the entire subnet. Cannot be assigned to a host.
      • Broadcast Address (host portion all ones — e.g., 192.168.1.255/24): a packet sent here is delivered to every host in the subnet. Cannot be assigned to a host.
      • Loopback Range (127.0.0.0–127.255.255.255): reserved for testing the local device's own TCP/IP stack. Traffic never leaves the device. The most commonly used loopback address is 127.0.0.1.

      CIDR (Classless Inter-Domain Routing):-

      CIDR (Classless Inter-Domain Routing) replaced the older classful networking system to prevent the rapid exhaustion of IPv4 addresses. The classful system assigned addresses in rigid fixed sizes:

      ClassFirst Octet RangeDefault MaskNetwork Size
      A1–126/8 (255.0.0.0)16,777,214 hosts — far too large for most organizations
      B128–191/16 (255.255.0.0)65,534 hosts — still too large for most

      The problem: a company needing 2,000 host addresses would receive an entire Class B network (65,534 hosts) — wasting over 63,000 addresses. CIDR (Classless Inter-Domain Routing) allows any prefix length. That same company could receive a /21 network (2,046 usable hosts) — a far more efficient allocation. CIDR is now universal in all modern networking.

      Subnet Masks — Fixed-Length and Variable-Length:-

      • FLSM (Fixed-Length Subnet Masks): all subnets use the same prefix length and therefore the same number of host addresses. Simple to design but inefficient when subnets have very different size requirements.
      • VLSM (Variable-Length Subnet Masks): different subnets use different prefix lengths, allowing each subnet to be exactly sized for its actual needs. A subnet for 100 hosts uses /25 (126 usable hosts); a point-to-point link uses /30 (2 usable hosts). VLSM (Variable-Length Subnet Masks) is the standard approach in modern network design.

      IPv4 Packet Header:-

      When a Layer 4 segment or datagram arrives at Layer 3, an IP header is added to create an IP packet. Every field in the header serves a specific purpose.

      Internet Header Length (IHL)4 bitsLength of the IP header in 32-bit words. Minimum = 5 (5 × 4 = 20 bytes, no options). Maximum = 15 (60 bytes, with options present).
      Differentiated Services Code Point (DSCP)6 bitsUsed for Quality of Service (QoS) — allows routers to prioritize delay-sensitive traffic such as voice calls and video.

      The Header Checksum protects only the IP header — not the payload data. Payload error detection is the responsibility of Layer 4: TCP (Transmission Control Protocol) and UDP (User Datagram Protocol) each have their own checksum fields.

      IP Fragmentation:-

      Every network link has a MTU (Maximum Transmission Unit) — the largest packet it can carry. For standard Ethernet, the MTU (Maximum Transmission Unit) is 1,500 bytes. If an IP packet exceeds the MTU of a link, the router fragments it. The receiving host — not intermediate routers — reassembles the fragments using the Identification, Flags, and Fragment Offset fields.

      TTL (Time to Live) and Routing Loops:-

      Without the TTL (Time to Live) field, a packet caught in a routing loop would circulate forever. Starting at 64 (recommended default), TTL is decremented by 1 at each router. When it reaches 0, the packet is dropped and an ICMP (Internet Control Message Protocol) 'Time Exceeded' error is returned to the source. This mechanism also underpins traceroute — which intentionally sends packets with TTL = 1, 2, 3, and so on to map the hops along a path.

      The Ping Utility:-

      Ping is a network diagnostic tool that tests whether a destination is reachable and measures the round-trip time (RTT). It uses ICMP (Internet Control Message Protocol) — sending an ICMP Echo Request to the destination and waiting for an ICMP Echo Reply. A successful reply confirms the path is working end-to-end.

      • ICMP Echo Request: sent by the initiating device to the target IP address.
      • ICMP Echo Reply: sent back by the target device if it is reachable.
      Note:

      When pinging a device on the same subnet for the first time, ARP (Address Resolution Protocol) must run first to resolve the destination MAC address. Only then can the ICMP packet be encapsulated in an Ethernet frame and sent. This is why the very first ping can occasionally be slow or fail.

      The Routing Table:-

      A router consults its routing table for every forwarding decision — a database mapping destination networks to the interface or next-hop address used to reach them. To view it on a Cisco router:

      show ip route

      The output shows a codes legend at the top listing all the protocols the router can use to learn routes, followed by the actual routing table entries.

      Route Codes — How Routes Are Learned:-

      • L — Local: a route to the exact IP address configured on this router's own interface. Uses a /32 prefix (e.g., 192.168.1.1/32) — the /32 mask has no host bits, matching exactly this one specific address.
      • C — Connected: a route to the network the interface is directly part of. Uses the actual configured subnet prefix (e.g., 192.168.1.0/24 — the entire subnet).
      • S — Static: a route manually configured by a network administrator using the 'ip route' command.
      • O — OSPF: a route learned from a neighboring router via the OSPF (Open Shortest Path First) dynamic routing protocol.
      Note:

      When you configure an IP address on an interface and enable it with 'no shutdown', two routes are automatically added: one Local (L) route for the interface's exact IP, and one Connected (C) route for the subnet. These appear automatically — they are neither static nor dynamic.

      Types of Routing:-

      • Dynamic Routing: routers automatically exchange routing information with neighboring routers and build their tables without manual intervention. When the network changes, routers update their tables automatically. Examples: OSPF (Open Shortest Path First), EIGRP (Enhanced Interior Gateway Routing Protocol), Border Gateway Protocol (BGP). Scales well for large networks.
      • Static Routing: a network engineer manually configures routes using the 'ip route' command. The router only knows what it is explicitly told and does not adapt automatically to topology changes. Appropriate for small networks or specific fixed routes.

      Configuring Static Routes:-

      Static routes are added to the routing table using the 'ip route' command. Three methods exist:

      • Method 1 — Next-Hop IP Address: specify the IP address of the next router in the path.
      ip route <destination-network> <subnet-mask> <next-hop-ip>

      Example: ip route 10.0.0.0 255.255.255.0 192.168.1.2

      • Method 2 — Exit Interface: specify which local interface the packet should leave through.
      ip route <destination-network> <subnet-mask> <exit-interface>

      Example: ip route 10.0.0.0 255.255.255.0 GigabitEthernet0/0

      • Method 3 — Both (recommended): specify both the exit interface and the next-hop IP address.
      ip route <destination-network> <subnet-mask> <exit-interface> <next-hop-ip>

      Example: ip route 10.0.0.0 255.255.255.0 GigabitEthernet0/0 192.168.1.2

      Default Route — Gateway of Last Resort:-

      A default route is a catch-all route that matches any destination IP address that does not match a more specific entry in the routing table.

      • Notation: 0.0.0.0/0 — both the network address and mask are all zeros. This matches every possible destination when no more specific route exists.
      • Behavior: when a router has no specific match for a packet's destination, it forwards using the default route. Without one, unmatched packets are dropped.
      • Common use: sending all internet-bound traffic toward the Internet Service Provider (ISP). Home routers use exactly this — a single default route handles all outbound internet traffic.
      • Terminology: called the Default Gateway on end hosts (PCs, servers); called the Gateway of Last Resort on routers, as shown in 'show ip route' output.
      ip route 0.0.0.0 0.0.0.0 <next-hop-ip>     → configure a default route

      Inter-VLAN Routing:-

      VLANs (Virtual Local Area Networks) create isolated Layer 2 broadcast domains. For hosts in different VLANs to communicate, their traffic must be routed at Layer 3. There are two main approaches:

      Router on a Stick (ROAS):-

      Router on a Stick (ROAS) routes between multiple VLANs using a single physical router interface connected to a trunk port on the switch. The router's physical interface is divided into logical subinterfaces — one per VLAN — each configured with its own IP address, which becomes the default gateway for hosts in that VLAN.
      FIGURE SPACE

      [ Figure: ROAS topology: Switch trunk port connects to Router G0/0. Router G0/0 is divided into subinterfaces: G0/0.10 (VLAN 10 gateway 192.168.10.1), G0/0.20 (VLAN 20 gateway 192.168.20.1), G0/0.30 (VLAN 30 gateway 192.168.30.1). ]

      int g0/0.10                               → create subinterface for VLAN 10
      encapsulation dot1q 10                    → handle frames tagged with VLAN 10
      ip address 192.168.10.1 255.255.255.0     → default gateway IP for VLAN 10 hosts

      Repeat for each VLAN. For the native VLAN, two options exist:

      • Option 1: use a subinterface and add the 'native' keyword: encapsulation dot1q 1001 native
      • Option 2: configure the IP directly on the physical interface — native VLAN frames arrive untagged, so no encapsulation command is needed.
      Note:

      Router on a Stick (ROAS) creates a bottleneck — all inter-VLAN traffic must travel through one physical cable to the router and back. For larger or higher-traffic networks, a Layer 3 (multilayer) switch is the preferred solution.

      Layer 3 / Multilayer Switches:-

      A multilayer switch (also called a Layer 3 switch) can both switch at Layer 2 and route at Layer 3. Inter-VLAN routing happens inside the switch itself at wire speed — eliminating the ROAS bottleneck entirely.

      Instead of an external router, each VLAN gets a SVI (Switch Virtual Interface) — a virtual Layer 3 interface on the switch that acts as the default gateway for hosts in that VLAN.

      Dynamic Routing Protocols

      Static routes require manual configuration and do not adapt to network changes. Dynamic routing protocols allow routers to automatically discover networks, share route information with neighbors, and update their routing tables when the topology changes.

      Dynamic Routing Fundamentals:-

      Routers running a dynamic routing protocol form adjacencies (also called neighbor relationships or neighborships) with directly connected routers and exchange routing information automatically. When multiple routes to the same destination are learned, the router selects the best one using the route's metric — a value that represents the cost of using that path. A lower metric is always preferred.

      Network route: a route to a network or subnet (e.g., 192.168.1.0/24).
      • Host route: a route to a single specific host, using a /32 prefix (e.g., 192.168.1.1/32).

      AD (Administrative Distance):-

      When a router learns routes from multiple different routing protocols, it needs a way to decide which protocol's routes to trust. AD (Administrative Distance) is a value assigned to each routing source that indicates its trustworthiness. A lower AD is more preferred.

      Floating Static Routes:-

      The Administrative Distance of a static route can be manually increased so that it is only used when a dynamic routing protocol's route to the same destination is no longer available:

      ip route <network> <mask> <next-hop> <AD>     → configure a static route with a custom AD

      This is called a floating static route. It sits in the background and becomes active only if the dynamic route disappears — for example, when a neighbor adjacency is lost or an interface fails.

      ECMP (Equal Cost Multi-Path):-

      If a router learns two or more routes to the same destination via the same routing protocol with the same metric, all routes are added to the routing table and traffic is load-balanced across them. This is called ECMP (Equal Cost Multi-Path). Most routing protocols support up to 4 ECMP paths by default.

      Distance Vector Protocols:-

      Distance Vector protocols share route information by sending their known destinations and metrics to directly connected neighbors only. Each router knows the direction (next hop) and distance (metric) to reach a destination, but has no knowledge of the full network topology beyond its neighbors. This is often called 'routing by rumor'. Examples: RIP (Routing Information Protocol), EIGRP (Enhanced Interior Gateway Routing Protocol).

      Link State Protocols:-

      Link State protocols work differently — each router advertises information about its own directly connected interfaces to all routers in the network. These advertisements (called LSAs (Link State Advertisements)) are flooded through the entire area until every router has an identical map of the network. Each router then independently runs the Shortest Path First (SPF) algorithm on this map to calculate the best routes. Link State protocols react faster to network changes than Distance Vector protocols, but use more CPU and memory resources. Examples: OSPF (Open Shortest Path First), Intermediate System to Intermediate System (IS-IS).

      RIP (Routing Information Protocol):-

      RIP (Routing Information Protocol) is a Distance Vector IGP (Interior Gateway Protocol). It uses hop count as its metric — each router in the path counts as one hop, regardless of bandwidth. The maximum hop count is 15; any destination more than 15 hops away is considered unreachable.

      Configuring RIP:-

      router rip                          → enter RIP configuration mode
      version 2                           → use RIPv2 (recommended)
      no auto-summary                     → disable automatic classful summarization (on by default — must be disabled for VLSM/CIDR support)
      network <network-address>           → activate RIP on interfaces matching this classful network range

      The 'network' command is classful — it automatically converts the address to its classful boundary. For example, 'network 10.0.12.0' becomes 'network 10.0.0.0' (Class A). The network command does not tell RIP which networks to advertise. It tells RIP which interfaces to activate on, and the router then advertises the actual prefix of each activated interface.

      passive-interface g#/#             → stop sending RIP advertisements out of this interface (still advertises the prefix to neighbors)

      EIGRP (Enhanced Interior Gateway Routing Protocol):-

      EIGRP (Enhanced Interior Gateway Routing Protocol) was originally Cisco-proprietary but has since been published as an open standard. It is considered an advanced or hybrid Distance Vector protocol. EIGRP reacts to topology changes much faster than RIP and has no hop-count limit. It uses multicast address 224.0.0.10 to communicate with neighbors. By default it performs ECMP (Equal Cost Multi-Path) over up to 4 paths — and uniquely, it is the only IGP (Interior Gateway Protocol) that can also perform unequal-cost load balancing.

      Configuring EIGRP:-

      router eigrp <AS-number>            → enter EIGRP configuration mode. The Autonomous System (AS) number must match on all routers — mismatched AS numbers prevent adjacency formation.
      no auto-summary                     → disable classful summarization
      network <ip-address> <wildcard-mask> → activate EIGRP on interfaces matching this range
      EIGRP uses a wildcard mask — the inverse of a subnet mask. A 0 bit in the wildcard mask means 'this bit must match'; a 1 bit means 'this bit can be anything'. Example: subnet mask 255.255.255.0 = wildcard mask 0.0.0.255.
      eigrp router-id <#.#.#.#>          → manually set the EIGRP Router ID
      show ip eigrp neighbors            → view established EIGRP neighbor adjacencies
      show ip eigrp topology            → view the EIGRP topology table (all learned routes, not just best routes)

      EIGRP Metric:-

      By default, EIGRP calculates its metric using bandwidth and delay: metric = bandwidth of the slowest link + cumulative delay of all links. The simplified formula is: Metric = (Bandwidth + Delay) × 256.

      • Feasible Distance (FD): this router's total metric to the destination.
      • Reported Distance (RD) / Advertised Distance (AD): the neighbor's metric to the destination (as reported to this router).
      • Successor: the route with the lowest Feasible Distance — the best route, installed in the routing table.
      • Feasible Successor: an alternate route whose Reported Distance is lower than the Successor's Feasible Distance. Meets the feasibility condition — a loop prevention mechanism. Feasible Successors are stored in the topology table as instant backups.

      EIGRP Unequal-Cost Load Balancing (Variance):-

      EIGRP can load-balance across routes with different metrics using the variance multiplier. Variance 1 (default) = only ECMP. Variance 2 = feasible successor routes with a Feasible Distance up to 2× the successor's Feasible Distance can participate in load balancing. EIGRP will only use Feasible Successors for unequal-cost load balancing — a route that does not meet the feasibility condition can never be used, regardless of variance.

      Router ID Priority Order (EIGRP and OSPF):-

      • Manually configured Router ID.
      • Highest IP address on a loopback interface.
      • Highest IP address on a physical interface.

      OSPF (Open Shortest Path First):-

      OSPF (Open Shortest Path First) is a Link State IGP (Interior Gateway Protocol). It uses Dijkstra's Shortest Path First (SPF) algorithm to calculate the best routes. OSPF routers store network topology information in LSAs (Link State Advertisements), which are organized in a LSDB (Link State Database). All routers in an OSPF area flood LSAs until every router has an identical LSDB, then each independently calculates the best routes.

      VersionUsage
      OSPFv1Original version. No longer used.
      OSPFv2Used for IPv4. The standard version in use today.
      OSPFv3Used for IPv6. Can also support IPv4 but OSPFv2 is typically used for IPv4.

      OSPF Areas:-

      OSPF divides the network into areas to improve scalability. In a large single-area OSPF network, every topology change causes all routers to re-run the SPF algorithm and reflood LSAs — consuming CPU, memory, and bandwidth. Dividing the network into multiple areas limits the scope of these updates.

      • Area 0 (Backbone Area): the central area that all other areas must connect to directly.
      • Internal Router: all interfaces are in the same OSPF area.
      • ABR (Area Border Router): has interfaces in multiple areas. Maintains a separate LSDB for each area. Recommended maximum of 2 areas per ABR — connecting to 3 or more areas can overburden the router.
      • Backbone Router: any router with an interface in Area 0.
      • ASBR (Autonomous System Boundary Router): an OSPF router that connects the OSPF network to an external network (e.g., the internet). Using 'default-information originate' makes a router an ASBR.
      • Intra-area route: a route to a destination within the same OSPF area.
      • Inter-area route: a route to a destination in a different OSPF area.
      Note:

      All OSPF areas must be contiguous (connected). All areas must connect to the backbone area (Area 0). OSPF interfaces in the same subnet must be in the same area.

      Configuring OSPF:-

      router ospf <process-id>            → enter OSPF configuration mode. The process ID is locally significant — routers with different process IDs can still become neighbors.
      network <ip-address> <wildcard-mask> area <area-id>  → activate OSPF on interfaces matching this range and assign them to the specified area

      Alternatively, OSPF can be activated directly on an interface:

      int <interface-id>

      router-id <#.#.#.#>                → manually configure the OSPF Router ID (same priority order as EIGRP)
      passive-interface <interface-id>   → stop sending OSPF Hello messages out of this interface (still advertises the subnet in LSAs)
      passive-interface default          → make ALL interfaces passive by default

      maximum-paths <number>             → change the maximum number of ECMP paths (default is 4)

      OSPF Metric — Cost:-

      OSPF's metric is called cost. It is calculated by dividing the reference bandwidth by the interface bandwidth. The default reference bandwidth is 100 Mbps:

      Interface SpeedCost (default 100 Mbps reference)Cost (100,000 Mbps reference — recommended)
      10 Mbps (Ethernet)100 / 10 = 10100,000 / 10 = 10,000
      100 Mbps (FastEthernet)100 / 100 = 1100,000 / 100 = 1,000
      1 Gbps (Gigabit)100 / 1,000 = 1 (min)100,000 / 1,000 = 100
      10 Gbps100 / 10,000 = 1 (min)100,000 / 10,000 = 10

      Because any value below 1 is rounded up to 1, FastEthernet, Gigabit, and 10 Gigabit all have the same default cost of 1 — which makes them indistinguishable to OSPF. To fix this, change the reference bandwidth to a value greater than your fastest link:

      auto-cost reference-bandwidth <Mbps>  → change the reference bandwidth (configure the same value on ALL OSPF routers)

      Three ways to set the OSPF cost on an interface (highest priority first):

      • Direct cost override: ip ospf cost <value> — takes priority over all other methods.
      • Change interface bandwidth: bandwidth <Kbps> — affects cost calculation but also affects EIGRP metric. Not recommended.
      • Change the reference bandwidth: auto-cost reference-bandwidth — affects all interfaces globally.

      The total OSPF cost to a destination is the sum of the costs of all outgoing (exit) interfaces along the path — the same concept as STP path cost. Loopback interfaces always have a cost of 1.

      OSPF DR and BDR:-

      On broadcast network types (Ethernet by default), OSPF elects a DR (Designated Router) and a BDR (Backup Designated Router) on each subnet to reduce the number of LSA exchanges. Without a DR/BDR, every pair of routers on the segment would need to form a full adjacency — creating n(n-1)/2 adjacencies for n routers.

      • DR: all routers on the segment form a Full adjacency with the DR and exchange LSAs through it.
      • BDR: monitors the DR and takes over if the DR fails.
      • DROther: any router that is not the DR or BDR. DROthers form a Full adjacency only with the DR and BDR — they remain in the 2-Way state with other DROthers.

      DR/BDR election priority order:

      • Highest OSPF interface priority (default is 1 on all interfaces — set to 0 to prevent a router from being elected DR/BDR).
      • Highest OSPF Router ID.

      'First place' becomes the DR; 'second place' becomes the BDR. The election is non-preemptive — once elected, the DR and BDR keep their roles until OSPF is reset or the interface fails.

      ip ospf priority <0-255>            → change the OSPF priority on an interface (0 = never DR/BDR)

      When the DR goes down, the BDR immediately becomes the new DR, and a new BDR election is held among the remaining DROthers.

      OSPF Neighbor States:-

      OSPF routers go through a series of states before establishing a full adjacency and exchanging their LSDBs:

      StateDescription
      DownOSPF activated on the interface. Hello messages sent to 224.0.0.5. No neighbors known yet.
      InitA Hello packet was received from a neighbor, but this router's own Router ID is not yet in the neighbor's Hello packet.
      2-WayBoth routers have seen each other's Router ID in Hello packets. All conditions for adjacency are met. On broadcast networks, the DR/BDR election occurs here. DROthers remain in the 2-Way state with each other.
      ExstartThe routers negotiate which will be Master (higher Router ID) and which will be Slave before exchanging DBD (Database Description) packets.
      ExchangeRouters exchange DBD (Database Description) packets — summaries of their LSDBs — to find out what LSAs the other router has.
      LoadingRouters send LSR (Link State Request) messages to request specific LSAs they are missing. LSAs are delivered in LSU (Link State Update) messages and acknowledged with LSAck messages.
      FullRouters have identical LSDBs and a complete OSPF adjacency. They continue exchanging Hello packets to maintain the adjacency (Hello every 10 s, Dead timer 40 s).
      Note:

      OSPF Hello messages are multicast to 224.0.0.5 (all OSPF routers). Messages to the DR (Designated Router) and BDR (Backup Designated Router) use 224.0.0.6. OSPF is encapsulated directly in IP with Protocol field value 89.

      On serial interfaces, one side functions as DCE (Data Communications Equipment) and the other as DTE (Data Terminal Equipment). The DCE side must set the clock rate (speed):

      clock rate <bits-per-second>        → set the clock rate on the DCE side of a serial link
      show controllers <interface-id>    → identify which side is DCE and which is DTE

      The default encapsulation on serial interfaces is Cisco HDLC (cHDLC). To change it (must match on both ends):

      encapsulation <ppp|hdlc>            → change the serial encapsulation

      To change the OSPF network type on an interface:

      ip ospf network <broadcast|point-to-point|non-broadcast>   → override the default network type
